### Actual Head / Neck / Chest rotation logger (2026-10-14)

The **scene-only** `TitanV017ArenaAimRotationQA` on `TITAN_V017_ACTIVE_ALL_COMPONENTS_TEST_RIG` runs in a late `LateUpdate` (execution order 32000) and logs the **evaluated real bones**, not just a desired constraint weight. No bone, target, animation or IK values are modified by the logger.

1. Enter isolated Play Mode and open **Window > General > Console**. Enable Info/Log messages and filter text **`[TITAN AIM ROT QA]`**. A line is emitted approximately every **0.75s**; select the Titan root and inspect the `TitanV017ArenaAimRotationQA` component to change `Log Rotations` or `Log Every Seconds` in the **arena only**.
2. Stand Van in front, then move him left/right using WASD or the real mobile joystick. Compare the `HEAD worldDeltaBaseline` and `worldDeltaLast` values, `NECK deltaBaseline`/`deltaLast`, `CHEST deltaBaseline`/`deltaLast`, and the `actualAimError` angles toward Van's **real Spine2**. `VAN directionDelta`, `yaw`, `elevation` and `proxyLag` show how much the target moved and how the target smoothing responds.
3. `HEAD localDeltaBaseline=0` **does not mean the head failed to move**: the Head bone inherits actual rotation from its parent `mixamorig:Neck`. The **Head WORLD** quaternion measures this inherited movement. `CHEST actualAimError` is a support-contribution diagnostic, **not** an assertion that the chest should fully point at Van.
4. `deltaBaseline` measures change from the **first sample in the current Animator state**; it resets on changing Animator states. `deltaLast` measures change since the previous sampled report. These values include any native animation movement, so proving that *procedural attention* caused a change requires comparing the target/weights over time in the same held Animator state. No telemetry number alone overrides the human visual FAIL.
5. The component context menu **`QA: Log ACTUAL Head and Chest Rotations Now`** provides an on-demand sample while Play Mode is running.

In actual isolated Play Mode at idle, the logger recorded roughly **Head WORLD Δ=29.09°**, **Neck LOCAL Δ=26.94°**, **Chest LOCAL Δ=2.16°**, and a reduction of **Neck Z-axis aim error 35.96° → 7.70°** as its weight rose to 0.78 and chest weight to 0.22. After the Van test target moved laterally, logs also recorded further Head/Neck world response, proving that the constrained bones change with real target direction. **Visual QA is still FAIL** until chest pitch and face orientation look genuinely natural.

## 2026-10-14 follow-up: isolated Write Defaults ON test and 4/4 breakthrough (experimental)

- **Root cause supported by Unity's Animation Rigging team:** With an Animator state using `writeDefaultValues=false`, Animation Rigging's scene constraint values can be overridden by the animation stream even though the selected clip contains no explicit constraint-weight curves. See Unity Discussions `Animation Rigging with Multiple Animator Layers` (Unity team response, July 2021) and `Animation Rigging animation states with Write Defaults unchecked locks Constraints`. This explains the recorded **same frame Update 1.000 / LateUpdate 0.000** IK weight observations. Earlier experiments changed *AwakenedHold* to Write Defaults **OFF**, which did not address the V017 state itself.
- Created **isolated controller clone** `Titan_TestArena/TitanV017_WriteDefaultsON_StompProof.controller` and rebound only the arena's active Titan Animator. Changed only the clone's **`Base Layer.ColossalStompRightFootV017`** state to `writeDefaultValues=true`, keeping the exact same source `.anim` clip, Avatar, and remaining controller states. The production `Titan_V017_Stage3Boss.controller` retains its original `writeDefaultValues=false`. At the first impact, logs now confirm **Update=1.000 and LateUpdate=1.000**, resulting in an objectively certified first deformed-mesh ground contact rather than 0/4.
- Adjusted corrective right IK recovery to reduce weight **before** the giant mocap hip moves outside the preserved 94% limit (and left corrective IK to disengage before its analogous hard reach cap), reverting to **original authored** recovery/support rather than stretching legs or increasing the cap. These changes are in `TitanV017FourRightStompIKPreview.cs`; they do **not** touch Astra's original clip.
- **First complete replay PASSED**: four separately verified physical and deformed-mesh contacts, with right mesh planar/height errors ~`0.024/0.002`, `0.062/0.022`, `0.023/0.007`, `0.071/0.001` world metres for stomps 1–4. Left mesh stayed ground-aligned at the measured impact frames. The controller completed the original clip before reporting PASS, with zero gameplay damage/CC.

Do not collapse this outcome to '4/4 always passes.'
